# Digital Store Frontend (Angular)

واجهة متجر أجهزة مبنية بـ Angular 21 باستخدام Standalone Components، مع تجربة عربية أولًا، دعم RTL، ومسارات منفصلة للمستخدم العادي وللأدمن.

هذا الـ README مخصص للفرونت فقط. الهدف منه أن أي شخص يدخل المشروع يفهم بسرعة:
- ما الذي يقدمه الموقع للمستخدم
- ما هي الصفحات الموجودة
- ما هي الـ features المنفذة
- كيف تم تنظيم كود الواجهة

## نظرة عامة على الموقع

الموقع هو واجهة متجر إلكتروني لبيع الأجهزة والمنتجات التقنية. التجربة الأساسية تمر بهذه الرحلة:

1. المستخدم يتصفح المنتجات.
2. يدخل على تفاصيل منتج معين.
3. يضيفه إلى السلة أو المفضلة.
4. يجهز العنوان وطريقة الشحن.
5. ينشئ الطلب ويدفع.
6. يتابع حالة الطلب والشحنة.
7. لو احتاج، يقدّم طلب إرجاع أو استرداد.

وفي نفس الوقت يوجد مسار خاص بالأدمن لإدارة:
- الكتالوج
- الطلبات والشحن
- الكوبونات
- الإرجاع والاسترداد
- شاشات الإدارة والملخصات

## ما الذي يوجد داخل الموقع فعليًا

### 1. المتجر والواجهة العامة
- صفحة عرض كل المنتجات مع البحث والفلترة والترتيب.
- صفحة تفاصيل المنتج.
- واجهة عربية RTL.
- شريط تنقل علوي واضح للمستخدم.
- تجربة متجاوبة على الشاشات الكبيرة والموبايل.

### 2. حساب المستخدم
- تسجيل الدخول.
- عرض بيانات الحساب.
- إدارة العناوين.
- عرض الطلبات.
- عرض المفضلة.
- مركز إشعارات داخل الموقع.

### 3. دورة الشراء
- سلة مشتريات.
- صفحة Checkout.
- اختيار عنوان الشحن.
- اختيار طريقة الشحن.
- إنشاء الطلب قبل الدفع.
- استكمال الدفع لاحقًا لو تم إنشاء الطلب ولم يكتمل الدفع.
- إلغاء الطلب حسب الحالة المسموح بها.

### 4. ما بعد الشراء
- صفحة "طلباتي".
- تتبع الشحنة بخط زمني.
- صفحة تتبع مستقلة لكل طلب.
- نظام طلبات الإرجاع والاسترداد.

### 5. لوحة الإدارة
- لوحة إدارة رئيسية.
- صفحة ملخصات تشغيلية.
- إدارة المنتجات والكتالوج.
- إدارة الطلبات والشحن.
- إدارة طلبات الإرجاع.
- إدارة الكوبونات.

## خريطة الصفحات الرئيسية

### صفحات المستخدم
- `/products`
  - الصفحة الرئيسية الفعلية للمتجر.
  - تعرض جميع المنتجات.
  - فيها بحث، فلترة، ترتيب، والتعامل مع حالة المخزون.

- `/products/:id`
  - صفحة تفاصيل المنتج.
  - تعرض معلومات المنتج وصوره وتفاصيله.
  - نقطة الدخول الطبيعية للإضافة إلى السلة أو المفضلة.

- `/cart`
  - مراجعة العناصر المختارة.
  - تعديل الكميات أو المتابعة للدفع.

- `/checkout`
  - صفحة إتمام الطلب.
  - اختيار العنوان وطريقة الشحن.
  - إنشاء الطلب.
  - إدخال بيانات الدفع.
  - تدعم استكمال الدفع على طلب تم إنشاؤه سابقًا ولم يكتمل.

- `/addresses`
  - إدارة عناوين الشحن الخاصة بالمستخدم.

- `/orders`
  - صفحة كل طلبات المستخدم.
  - تعرض حالة كل طلب.
  - فيها إجراءات مرتبطة بالطلب مثل:
    - استكمال الدفع للطلبات غير المدفوعة
    - إلغاء الطلب في الحالات المسموح بها
    - الانتقال لتتبع الشحنة

- `/orders/:id/tracking`
  - صفحة مخصصة لتتبع الشحنة.
  - تعرض حالة التوصيل الحالية.
  - تعرض بيانات التتبع مثل رقم التتبع، شركة الشحن، الموقع الحالي، الملاحظات، وموعد التسليم المتوقع.
  - تعرض timeline للتحديثات إن وُجدت.

- `/returns/new`
  - إنشاء طلب إرجاع جديد.
  - واجهة مخصصة لتسهيل اختيار الطلب المؤهل بدل كتابة رقم الطلب يدويًا.

- `/returns/my`
  - عرض كل طلبات الإرجاع الخاصة بالمستخدم.
  - توضح حالة كل طلب إرجاع، مبلغ الاسترداد إن وجد، وملاحظات الإدارة.

- `/notifications`
  - صفحة مركز الإشعارات داخل الموقع.
  - مخصصة للإشعارات الداخلية فقط.

- `/wishlist`
  - قائمة المفضلة.

- `/profile`
  - صفحة الحساب والبيانات الشخصية.

- `/auth`
  - صفحة تسجيل الدخول للمستخدم غير المسجل.

### صفحات الإدارة
- `/admin`
  - صفحة لوحة الإدارة الرئيسية.
  - مدخل سريع لبقية شاشات الإدارة.

- `/admin/overview`
  - ملخصات تشغيلية ومؤشرات سريعة.

- `/admin/catalog`
  - إدارة المنتجات والتصنيفات المرتبطة بالعرض.

- `/admin/orders`
  - إدارة الطلبات والشحن.
  - تحديث حالة الشحن.
  - إدخال رقم التتبع وبيانات شركة الشحن.
  - تعديل معلومات التتبع وربطها بالطلب.

- `/admin/returns`
  - إدارة طلبات الإرجاع والاسترداد.
  - فلترة حسب الحالة.
  - فتح التفاصيل.
  - تحديث الحالة وفق transitions المسموحة.

- `/admin/coupons`
  - إدارة الكوبونات وخصومات الطلبات.

## شرح الـ Features المنفذة

### 1. كتالوج المنتجات
هذه أول feature يراها المستخدم داخل الموقع.

تشمل:
- استعراض كل المنتجات
- البحث بالاسم أو الوصف أو SKU
- الفلترة حسب التصنيف
- الفلترة حسب السعر
- الفلترة حسب التوفر
- ترتيب النتائج

الهدف منها أن المستخدم يصل للمنتج بسرعة دون التنقل العشوائي.

### 2. تفاصيل المنتج
توفر الصفحة:
- اسم المنتج
- السعر
- الصور
- التوفر في المخزون
- الوصف
- الإجراءات الأساسية مثل الإضافة إلى السلة أو المفضلة

هذه الصفحة هي نقطة التحويل الأساسية من التصفح إلى الشراء.

### 3. السلة
السلة هي مرحلة المراجعة قبل بدء الطلب.

تدعم:
- عرض العناصر المختارة
- تعديل الكميات
- إزالة العناصر
- حساب الإجمالي
- الانتقال إلى الـ checkout

### 4. Checkout والدفع
من أهم الـ flows الموجودة في المشروع.

تشمل:
- اختيار العنوان
- اختيار طريقة الشحن
- تسعير الطلب
- إنشاء الطلب
- الدفع بالبطاقة
- التعامل مع رسائل الخطأ القادمة من بوابة الدفع بطريقة أوضح للمستخدم

ومن التحسينات المنفذة:
- منع رسائل الدفع الغامضة قدر الإمكان
- توضيح أخطاء الإدخال مثل اسم حامل البطاقة بالإنجليزية
- دعم استكمال الدفع لاحقًا لو تم إنشاء الطلب ولم يُدفع مباشرة

### 5. استكمال الدفع لاحقًا
هذه feature مهمة في التجربة الحالية.

سيناريوها:
- المستخدم أنشأ الطلب
- خرج من الصفحة أو أغلق المتصفح
- لم يكمل الدفع

الواجهة تدعم:
- استعادة الطلب غير المدفوع
- فتح صفحة الدفع عليه مرة أخرى
- عدم ضياع الطلب على المستخدم

### 6. إدارة الطلبات للمستخدم
صفحة الطلبات ليست مجرد عرض تاريخي، بل واجهة تشغيلية للمستخدم.

توفر:
- عرض كل الطلبات
- عرض الحالة الحالية لكل طلب
- عرض التفاصيل المختصرة
- الدخول إلى صفحة تتبع الشحنة
- استكمال الدفع عند الحاجة
- إلغاء الطلب وفق حالة الطلب

### 7. إلغاء الطلب
ميزة الإلغاء موجودة في الفرونت مع منطق واضح لإظهار الإجراء أو إخفائه.

الفكرة الأساسية:
- لا يظهر زر الإلغاء لكل الحالات
- يظهر فقط عندما تكون حالة الطلب تسمح بذلك
- لا يظهر إذا وصل الطلب إلى مرحلة لا يجب بعدها السماح بالإلغاء مثل:
  - `out_for_delivery`
  - `delivered`

هذا يجعل تجربة المستخدم أوضح ويمنع أفعال غير منطقية من الواجهة.

### 8. تتبع الشحنة
تم تنفيذ تجربة تتبع مستقلة للطلب.

تدعم:
- عرض حالة الشحن الحالية
- ترجمة الحالات إلى نص مفهوم عربيًا
- timeline للتحديثات
- عرض:
  - رقم التتبع
  - شركة الشحن
  - الموقع الحالي
  - الملاحظات
  - موعد التسليم المتوقع
- زر خارجي للتتبع إذا كان رابط التتبع متوفرًا

### 9. مركز الإشعارات
الموقع يحتوي على Notifications Center داخلي.

يوجد:
- جرس إشعارات في الهيدر
- معاينة سريعة لأحدث الإشعارات
- صفحة كاملة لعرض كل الإشعارات
- دعم عداد unread

المقصود هنا إشعارات داخل النظام فقط، وليس واتساب أو SMS أو خدمات خارجية.

### 10. العناوين
المستخدم يمكنه إدارة عناوين الشحن الخاصة به بدل إعادة إدخالها كل مرة.

هذا يساعد في:
- تسريع checkout
- تقليل أخطاء العنوان
- تحسين تجربة الشراء المتكرر

### 11. المفضلة
ميزة المفضلة تسمح للمستخدم بحفظ المنتجات التي يريد الرجوع إليها لاحقًا.

### 12. طلبات الإرجاع والاسترداد
تم بناء flow إرجاع واضح على الفرونت.

من جهة المستخدم:
- إنشاء طلب إرجاع
- اختيار السبب
- كتابة تفاصيل إضافية عند الحاجة
- متابعة حالة طلب الإرجاع
- إلغاء طلب الإرجاع إذا كانت حالته تسمح

ومن جهة الأدمن:
- عرض جميع طلبات الإرجاع
- الفلترة حسب الحالة
- فتح التفاصيل
- تحديث الحالة
- تسجيل ملاحظة إدارية
- تحديد مبلغ الاسترداد عند الحاجة

### 13. لوحة الإدارة
لوحة الإدارة في الفرونت مقسمة بدل أن تكون شاشة واحدة مزدحمة.

الهدف منها:
- فصل المسؤوليات
- جعل كل نوع من الإدارة له صفحة مناسبة
- تحسين قابلية التطوير لاحقًا

### 14. إدارة الكتالوج
هذه feature مخصصة للأدمن لإدارة المنتجات المعروضة في المتجر.

### 15. إدارة الطلبات والشحن
هذه من أهم صفحات الأدمن.

تدعم:
- تعديل حالة الشحن
- تحديث بيانات الشحنة
- ربط رقم التتبع وشركة الشحن
- تحسين انتقالات الحالة من داخل الواجهة

### 16. إدارة الكوبونات
واجهة للأدمن لإدارة العروض والكوبونات المستخدمة أثناء الشراء.

### معنى كل جزء

#### `core/guards`
فيها الحماية الخاصة بالمسارات:
- `authGuard` للصفحات التي تحتاج تسجيل دخول
- `adminGuard` لصفحات الأدمن فقط
- `guestGuard` لصفحات الضيف
- `checkoutAccessGuard` لمنع الدخول غير الصحيح إلى صفحة الدفع

#### `core/interceptors`
تتعامل مع الطلبات الخارجة إلى الـ API مثل إضافة التوكن.

#### `core/models`
تحتوي على أنواع البيانات والعقود المستخدمة بين الواجهة والـ API.

#### `core/services`
الخدمات المسؤولة عن التكامل مع الـ API، مثل:
- `auth.service.ts`
- `products.service.ts`
- `cart.service.ts`
- `orders.service.ts`
- `payments.service.ts`
- `tracking.service.ts`
- `returns.service.ts`
- `notifications.service.ts`

#### `core/utils`
تجميع الـ helpers والمحوّلات والمنطق القابل لإعادة الاستخدام.

#### `features/*`
كل feature لها مجلدها الخاص، وهذا يسهل:
- فهم المشروع
- الصيانة
- التطوير المستقبلي

## ملاحظات مهمة لأي مطور يدخل المشروع

بعض الأزرار لا تظهر إلا حسب الحالة، مثل:
- استكمال الدفع

- حالة loading
- حالة error
- أو رسائل توضح أن البيانات غير متاحة

### 4. تم تحسين عدد من الـ flows الحساسة
من أهمها:
- الدفع
- استكمال الطلب غير المدفوع
- تتبع الشحنة

- إشعارات الموقع

## Support SSE auth + unread behavior

- دعم الـ SSE في صفحات الدعم (عميل + أدمن) أصبح يعتمد على `Authorization: Bearer <token>` بشكل صريح.
- تم استبدال الاتصال المباشر بـ `EventSource` بطبقة مخصصة:
  - [support-stream.service.ts](/d:/Programming/E-Commerce/front_End/angular-starter/src/app/core/services/support-stream.service.ts)
  - تتولى `connect/disconnect` + reconnect بآلية exponential backoff.
- العدادات غير المقروءة أصبحت server-driven بالكامل:
  - `unreadCount` من قائمة التذاكر
  - و`/support/tickets/unread-count` و`/admin/support/tickets/unread-count`
- عند فتح تفاصيل التذكرة يتم استدعاء `GET /support/tickets/:id` (أو نسخة الأدمن) ثم تحديث عداد غير المقروء فورًا، لأن القراءة أصبحت per-message read receipts من الباك.
- في حالة rate limit (`429`) داخل صفحات الدعم:
  - تظهر رسالة واضحة للمستخدم
  - مع زر "إعادة المحاولة"
  - بدون حلقات retry عدوانية.
